# Fixed SH4 execution

`scripts/compile_sh4.py` translates exact, hash-verified BIOS/cartridge bytes
before compilation. Original-execution observations validate the resulting
coverage and cannot add executable entries. Generated programs
and native objects remain under ignored `build/` directories.

Each original PC selects an immutable expected instruction and a fixed C++
operation. The instruction word fetched by the original cache/MMU path is
checked against that identity; it is never used to index a runtime opcode
decoder. Overlapping game/service loads and observed bootstrap copies have
separate authenticated variants. An unknown entry or changed word calls the
shared `vt_fixed_fault` helper, which records an inspectable error and throws
a controlled `FlycastException`.

The generator selects original integer/FPU operation bodies, register fields,
immediates, FPU-disabled classification, execution unit and cycle metadata
offline. Data memory remains live. FPSCR modes, architectural registers,
interrupts and exception handling remain runtime hardware state. The original
delay-slot and RTE fetch ordering is retained.

The build removes the original SH4 interpreter dispatch, integer/FPU opcode
objects, opcode-table construction and dynamic cycle classification. The
retained `Sh4Interpreter` class name is an ABI adapter for the original device
lifecycle; its execution method invokes the fixed PC map.

Typical development commands:

```sh
python3 scripts/build_reference_clock.py
python3 scripts/compile_sh4.py
python3 scripts/build_sh4.py
python3 scripts/verify_sh4_metadata.py
python3 scripts/verify_sh4_operations.py
```

An optional `--trace` argument to the compiler verifies that every observed
PC/word belongs to the fixed images. Such a trace must come from the separately
built original observer. It is not generated by the shipping CPU and does not
cause runtime compilation. `scripts/verify_sh4_images.py --trace TRACE` checks
the original loader execution and exact RAM witnesses independently.
The derived original reference and fixed execution both use SH4 cycle
multiplier one; the original interpreter's optional eightfold slowdown is
removed without enabling STRICT_MODE or changing any other hardware options.
`Documentation/sh4-translation.md` describes the evidence and limits.

The ROM-rooted Run optimization groups selected blocks and prevalidates guarded
register-only sequences. A separately guarded counter loop preserves complete
CPU/cycle/RAM state at its admitted boundaries. See
[`Documentation/sh4-run-optimization.md`](../../../Documentation/sh4-run-optimization.md)
for the exact admission, fallback and observation boundaries. The standard
preparation workflow runs differential fixtures against the actual emitted
objects before linking and verifies all 3,145,728 game/BIOS targets afterward.
